# はじめに

`SELECT name FROM users WHERE id = 42;` のようなSQLを1行実行したとき、その裏では何が起きているのでしょうか。

その1行が結果の1行になるまでに、SQL文字列は字句列、構文木、論理的な計画、物理的な実行計画という複数の中間表現へ姿を変え、パーサー、オプティマイザ、実行エンジン、ストレージエンジンという性質の異なる層を順に通過していきます。
`id`が列名だと確定する段階も、その値がディスクのどのページにあるかを特定する段階も、この時点ではまだ見えていません。

本書は、Rustで一から関係データベース管理システム(RDBMS)を作りながら、データベース内部の設計と実装を学ぶStep-by-step教材です。
[*Writing an OS in Rust*](https://os.phil-opp.com/) のRDBMS版を目指し、インメモリの最小実装から始め、ディスク永続化、クエリ最適化、トランザクション、クライアント/サーバー化まで、全40章(7部構成)にわたって一つのRustクレートを段階的に育てていきます。

## 対象読者

- Rustの基本文法(所有権、トレイト、エラー処理)を理解している人
- データベースの内部実装(ストレージエンジン、クエリ実行、トランザクション)に興味がある人
- 「動くコードを書きながら学ぶ」スタイルを好む人

データベース理論の事前知識は前提としません。
各章で必要な概念は、その都度導入します。

## 本書の構成

本書は次の7部(全40章)から構成されます。

- **第0部 設計と開発環境**(第1〜3章): 要件定義、クエリの一生の概観、プロジェクトの骨格
- **第1部 Bare Bones**(第4〜10章): 最小のインメモリSQLデータベース
- **第2部 Storage**(第11〜16章): ディスクへの永続化
- **第3部 Query Execution**(第17〜25章): SQLを実行計画へ変換する
- **第4部 Query Optimizer**(第26〜29章): よりよい実行計画を選ぶ
- **第5部 Transaction**(第30〜35章): ACIDと並行実行
- **第6部 Server、運用、品質保証**(第36〜40章): クライアント/サーバー化と品質保証

詳細な章立てはサイドバーの目次([SUMMARY](SUMMARY.md))を参照してください。

現在執筆済みなのは第1〜3章のみで、第4章以降は準備中です。
